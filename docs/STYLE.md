# Writing style for student material

Many students on this course do not have English as a first language. The
subject is already hard. The writing must not add to that.

## Rules

**Every word must do a job.** Delete anything that only sounds good.

**Short sentences.** One idea each. Split a long sentence into two.

**Simple words.** Use "use" not "utilise". Use "about" not "regarding". Use
"start" not "commence".

**Say what to do first.** Put the instruction at the front of the
paragraph. Put the reason after it, if the reason is needed.

**Never write about the course itself.** Do not explain why a task is
designed a certain way. Do not say "this is deliberate", "that is the
point", or "this is the lesson". Teach the thing. Set the task. Stop.

**No flourishes.** Avoid these patterns:

| Do not write | Write |
|---|---|
| "It is not X. It is Y." | "It is Y." |
| "That is the whole of it." | (delete) |
| "worth knowing", "worth having" | (delete, or say why in plain terms) |
| "which is exactly why…" | (delete) |
| "genuinely", "actually", "simply", "of course" | (delete) |
| long dashes — like this — for asides | full stops |

**No jokes, no encouragement, no drama.** State facts.

## Tone check

Read a paragraph aloud. If it sounds like a person performing, rewrite it.
If it sounds like a clear instruction, keep it.

## Example

Before:

> That last line matters more than it looks. A program only shows you what
> you ask it to show. Without `print`, the interpreter would still compute
> `seconds` — correctly — and then finish in silence. When one of your
> programs runs and appears to do nothing, this is usually why: it worked,
> and nobody asked it to report.

After:

> The last line matters. A program only shows what you tell it to show.
> Without `print`, Python calculates `seconds` and then stops. Nothing
> appears on screen. If your program runs and shows nothing, this is often
> the reason.
